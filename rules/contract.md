# 接口与行为契约

在澄清之后、计划之前锁定可观察行为。保持原有阶段 2 和保存确认节点；契约是实施、测试和可选测试包的共同依据。

## 1. 适用范围

新增/修改对外接口、鉴权、错误、数据转换或其他可观察行为时生成相应契约。非 API 需求仍有轻量契约，但不强行写 HTTP 表格；只填写命中部分。

| 形态 | 必要行为 |
|------|----------|
| HTTP | 方法/路径/鉴权、输入、实际状态码/响应、错误与副作用 |
| RPC/事件 | 方法/消息/schema、结果/错误、时序与交付语义 |
| 函数/库 | 输入输出、错误/异常、边界和副作用 |
| CLI | 参数、stdout/stderr、退出码、文件变化 |
| 前端 | 操作、状态变化、可见反馈、加载/失败与必要可访问行为 |
| 异步任务 | 触发、结果、失败、必要重试/幂等要求 |

以当前项目指令、类型/schema、同类实现、样本或用户确认作为来源，不猜字段名、状态码、响应封装或旧兼容策略。未明确的信息标为待确认。

## 2. 保存与关系

默认 `agent_docs/contracts/YYYY-MM-DD-<feature>-contract.md`；遵守项目文档政策，按主流程展示和确认后保存，只创建必要目录。

契约回答行为与断言，计划回答路径、结构和实施步骤，不互相复制。冲突时提示并经确认同步，不能静默按代码覆盖契约。

## 3. 精简模板

```markdown
# <功能名称> 接口契约
**创建时间**：YYYY-MM-DD
**目标**：<行为目标>
**关联计划**：<已确定或待创建的计划路径>
**来源**：<当前项目的实际规则/类型/样例>

## 行为清单
<接口、函数、命令、交互或任务；注明新增/修改及边界>

## 输入与输出
<实际类型、约束、默认值、字段关系/优先级、状态与副作用>

## 错误与边界
<错误/异常/失败反馈、权限、空值、兼容要求；仅列适用项>

## 场景与断言
| 场景 | 输入或操作 | 预期结果 | 关键断言 |
|------|------------|----------|----------|
| 正常 | ... | ... | 至少一个可观察行为断言 |
| 失败/边界 | ... | ... | 错误与副作用符合约定 |

## 接口测试包适用性
<HTTP 场景可标识为 Apifox 场景矩阵；非 API 写“本次无外部 API 变更”并说明不适用原因；其他协议按实际工具能力说明>
```

HTTP 需求在输入输出部分补充 method/path、鉴权、参数位置、必填、默认值、成功/失败状态与响应表示；可为 JSON、空响应、文件或流，不预设 `code/data/rows`。HTTP 状态检查不能替代业务断言。

## 4. 查询与数据语义

搜索/筛选字段写清业务含义、匹配目标、字段关系、空值、多路径优先级和去重。对易混字段提供能区分错误映射的场景；内部存储列的实施映射放计划，必要时交叉引用。

## 5. 边界与输出

不写完整实现、代码修改清单或 TDD 拆分。覆盖本次相关正常/失败/边界，不复制无关历史接口。复杂 HTTP 测试包预计超过 30 条用例时先确认覆盖深度。

人类可读文本中文，代码、命令、API 方法/路径、字段、错误码与机器标识保持原样。缺少来源或与计划/实现冲突时先明确问题，不生成假定契约。
