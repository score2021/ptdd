# 阶段 0：项目识别与上下文加载

在原有阶段 0 内识别项目并复用既有规范，不增加独立初始化流程。本文件是加载、适用范围与降级行为的唯一权威来源。

## 1. 定位目标并加载上下文

1. 根据用户目标、当前工作目录和版本控制边界确定目标项目与本次模块。非 Git 项目使用明确的工作目录，不要求先建仓库。
2. 读取适用于该路径的项目指令；根 AGENTS.md 不存在时可补查 `agent_docs/AGENTS.md`，并遵守宿主已加载的上级/嵌套项目指令。PTDD 不要求转换其他宿主指令格式。
3. 读取 `<skill>/preferences/global-preferences.md`（L1）和目标项目已有的 `agent_docs/preferences/project-rules.md`（L2，可能无）。
4. 按需检查目标模块配置、依赖锁文件、测试配置、构建脚本、CI 与 1-3 个同类实现。只记 `agent_docs/` 索引，命中再读。

先识别本次模块，再识别工具链。多语言仓库按涉及的模块分别解析；不要从根目录单个配置推断整个仓库。排除依赖目录、vendor、生成物和无关嵌套项目。

## 2. 只保留本次执行需要的信息

在工作记忆中记录：

| 信息 | 核对方式 |
|------|----------|
| 项目/模块目录、项目形态 | 用户目标、入口、现有结构 |
| 语言、运行时、包管理/环境 | 配置、锁文件、版本声明、CI；不设语言白名单 |
| 架构、组件与测试组织 | 项目规范及同类实现；不强套 handler/service/DAO |
| 定向测试、回归、类型检查、构建、覆盖率命令 | 项目指令、脚本/任务定义、CI、测试配置；核对运行目录与参数转发 |
| 前置条件和未知项 | 所需服务、环境变量名称、工具可用性；不读取或记录凭据值 |

区分“配置已声明”“已执行验证”“推断/待确认”。识别工具名称不等于已验证命令；不凭某个配置文件就假设包管理器、测试框架或运行环境。

只读识别不执行依赖安装、生命周期脚本、构建或测试；实际运行留给计划约定的 TDD 环境检查与验收。无测试配置时记缺口，在阶段 1/3 确认最小方案，不自动安装框架。

## 3. 规则解析与冲突

- 用户要求和宿主生效的项目指令优先遵守，PTDD 文档不能覆盖这些指令。
- 在上述边界内，适用的项目偏好 L2 > 全局偏好 L1 > 已核对的项目证据 > 通用默认。
- 先过滤适用范围，再解析优先级。某项目或技术栈专属偏好不得带入不适用的模块；未声明范围的旧技术偏好遇到冲突时标记待澄清，不强行迁移项目。
- 配置、锁文件、源码和 CI 是实际技术事实的证据。偏好要求的工具尚不存在时，在计划中说明差异与必要配置，不能声称已经可运行。
- 不冲突的约束合并使用；真正影响决策的冲突在阶段 1 一次只问一个关键问题。计划与契约冲突沿用原有确认机制。

## 4. 输出与项目切换

正常最多两行，例如：

```text
已识别：<目标模块>；<实际技术栈/项目形态>；复用 <规范/配置来源>。
验证入口：<命令及运行目录>（尚未运行）；<仅列必要前置条件或缺口>。
```

切换项目或目标模块时，重新绑定并清除旧项目专属规则；路径变化但仍是同仓库 worktree 时仅复核受影响的环境。相关配置变化时只重读对应来源，不对每次业务代码修改做全仓扫描。

仅发现实际不适配或验证缺口才简短提醒一次，例如“当前模块测试入口未确认，不能沿用上一项目命令”。不按语言变化推断能力下降，不推送多选菜单、不自动派生 skill。确有反复出现的专项规则时，用户可另行要求创建专用 skill。

## 5. 缺少规范时的降级

- 无 AGENTS.md、L2 或 `agent_docs/` 均不报错，不要求先初始化；继续用项目配置与同类实现。
- 无配置或项目为空时，不猜测技术选型，把必要问题留到阶段 1。
- 无可验证命令不妨碍澄清和规划；进入 TDD 的对应任务前必须补齐测试入口及前置条件。
- 已有规范足够时直接复用，不建议重复建立文档。只有确有需长期复用且现有来源无法表达的规则时，才建议补入已有 L2。

## 6. 用户要求保存规则时

用户明确要求“初始化当前项目”时，先执行同一套只读识别，展示结论；已有信息足够就结束，不为初始化额外创建文件。

用户要求保存项目规范时，参考 `preferences/project-rules.template.md`，仅在 `agent_docs/preferences/project-rules.md` 补充少量已确认的特殊规则或来源指针，保留人工内容；不复制整份配置、目录树或通用知识。

用户要求创建 AGENTS.md 时，按需提供精简项目指令并使用实际有效的引用，不写不存在的文档路径，不自动创建空目录树或声明所有客户端都会自动加载。保存后回到原流程。

## 7. 边界

不新增 profile、初始化状态、配置指纹、语言规则包或全局项目注册表；不改全局 skill 来适配单个项目。阶段 0 不额外询问是否进入下一阶段，按主流程轻衔接进入阶段 1。
