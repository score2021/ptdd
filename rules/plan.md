# 实施计划

计划负责“怎么改”：精确路径、关键结构、TDD 任务与验收命令。行为由阶段 2 的契约负责，计划引用、不重复；不改变原有保存与确认节点。

## 1. 零上下文与职责分离

让不了解项目的人也能执行：明确目标模块、来源、涉及文件与预期结果。结构和命令必须来自当前项目，不能套用某语言的路径和架构。计划与契约冲突先同步确认，不进入冲突部分的实施。

## 2. 按需读取细则

| 场景 | 规则 |
|------|------|
| 查询/筛选/排序/聚合/唯一性/状态流转涉及字段映射 | `rules/plan-field-mapping.md` |
| 请求边界、交互、错误、日志、数据访问、事务、任务或外部依赖 | `rules/plan-conventions.md` |
| 每次检查交付范围 | `rules/plan-git-hygiene.md` |

## 3. 仅展示结构

列职责、签名或结构骨架，不输出完整实现。代码骨架使用目标项目的语言与既有接口；不依赖示例中的固定函数、类型、库或文件后缀。

实现要点应说明校验、业务处理、错误/状态反馈与边界，不复制契约的全部字段、场景与断言表。

## 4. TDD 任务顺序

每个行为任务包含：写测试 → 运行并确认有效 RED → 最小实现并 GREEN → 修改范围检查 → 有字段映射时核对来源 → REFACTOR → 定向/相关回归及最终验收。

写清实际运行目录与完整命令、预期失败原因和通过标准。不能只写“运行测试”；不能把依赖缺失或零测试当作有效 RED/GREEN。覆盖率 ≥ 80%，指标与范围明确；项目更严格阈值继续生效。

## 5. 复用上下文与精简输出

依据阶段 0 生效规则和项目证据。无 AGENTS.md 或 L2 不强制建文件、不反复提示初始化；已有规范足够则直接引用。确有需长期保存的特殊规则时，经用户授权补入既有 L2，不能用本次计划替代偏好文档。

默认保存到 `agent_docs/plans/YYYY-MM-DD-<feature>-plan.md`，遵守主流程确认节点和项目文档政策；人类文本中文，代码/命令/标识保持原样。

## 计划模板

```markdown
# <功能名称> 实施计划

**创建时间**：YYYY-MM-DD
**目标**：<一句话>
**架构**：<项目现有结构与本次方案>
**关联契约**：agent_docs/contracts/YYYY-MM-DD-<feature>-contract.md

## 项目惯例对齐
- 目标模块与参考实现：<实际相对路径及符号>
- 生效规则和命令来源：<已有指令、配置、脚本或 CI>
- 运行前置条件：<实际条件，未知项标注待确认>

## Git Hygiene
- 正式代码、测试与必要资产：<清单>
- 临时产物与忽略策略：<按项目政策>

## 任务 N：<可观察行为>
- 创建/修改/测试文件：<精确路径>
- 关键结构：<按实际语言仅列骨架或签名>
- 实现要点：<简短>
- RED：<命令、运行目录、目标行为缺失的失败>
- GREEN：<最小实现与通过命令>
- 检查：<改动范围；必要时字段映射>
- REFACTOR：<保持测试绿色>
- 验收：<相关回归与质量命令>

## 预期结果
- 契约场景有对应的有效测试。
- 目标测试和约定验收链通过；覆盖率指标、范围及至少 80% 门槛明确。
- 改动符合计划范围与生效规范，未声明未运行项通过。
```
