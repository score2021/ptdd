# 全局个人编码偏好（L1）

个人跨项目习惯，在阶段 0 结合目标项目解析。项目专属组件、技术选型和命令以当前项目证据及适用规范为准；不要把某次项目经验作为全局技术要求。

## 实现与复用

- 动手前用 `rg` 等方式调研同类实现，理解既有逻辑、边界与历史约束，再修改。
- 优先复用已有组件、数据访问、错误处理和日志方式；新增抽象前确认无可复用实现，在计划中说明必要性。
- 方案清晰直接，不为折中保留多套半新半旧的实现。
- 执行环境按当前项目、运行时和宿主实际情况确认，不固定操作系统或编程语言。

## 数据访问与错误处理

- 沿用项目已有 ORM、查询构建器或参数化查询方式，不强制引入某个库。
- 查询字段依据实际模型、schema、迁移或 DDL 核对，不把 UI 文案当存储字段。
- 复用项目错误类型、异常/结果模型及边界转换，不把内部实现信息直接暴露给调用方。

## 测试

- 沿用项目测试工具和组织方式，不因使用 PTDD 自动安装或替换框架。
- 保留 RED-GREEN-REFACTOR；依赖优先通过项目已有注入点替换，不用反射 hack，不为测试重造生产架构。
- Mock/fixture 的作用范围和恢复机制遵循项目规范，测试之间不能泄漏全局状态；显式禁止的替换方式不得使用。
- 覆盖率 ≥ 80%，写清指标、代码范围和命令，项目更严格阈值继续生效。
- 除 TDD 或已确认计划所需测试外，用户未要求时不新增独立测试脚本。

## 日志、注释与文档

- 直接复用项目 logger，字段结构与同类代码一致，不为单测方便新造 wrapper。
- 新增代码注释使用中文，文件保持 UTF-8；代码、路径、命令与机器标识保持原样。
- 代码、注释、日志、错误和测试名称中不使用 emoji。
- 用户未要求时，不额外编写项目说明类 Markdown；PTDD 契约和计划沿用原有保存与确认流程。

## 迁移与兼容

- 迁移先基于既有实现复制、改写和删减，不凭记忆重写。
- 兼容要求以项目和已确认契约为准；未要求兼容时不额外添加旧字段、旧行为或 fallback 分支。
- 不用兜底掩盖设计问题，优先定位并消除根因。
